# 去除人声按钮动画与播放页渲染开销

背景部分的性能改动后来按用户要求撤回，当前已 [恢复到掉帧反馈前的背景动画](background-animation-restore-20261013.md)。下文保留阶段记录，按钮与字体相关修复仍保留。

后续截图暴露的背景长条纹与按钮矩形细线，已在 [背景色带与按钮外框修复](background-bands-vocal-fringe-20261013.md) 中记录。下文是上一轮优化的验证记录。

## 按钮

原按压放大以中心为锚点，放大后的底边会落到布局底边之外；加法合成层只覆盖原布局矩形，因此下边会被裁切。激活后高度增长与按压缩放回落同时进行，容易看到底边向下移动。

- 缩放锚点固定为底边中心，按压和展开向上生长。
- `overlayEffect` 新增默认值为零的绘制留白参数；人声按钮使用 48 dp 留白容纳按压放大，其他控件维持原有边界。
- 展开高度约束在 34–94 dp，避免弹簧越过高度端点。
- 移除动画阴影及硬件轮廓裁切，始终以同一条 `YosRoundedCornerShape` 曲线的反向路径清除角外内容。清除发生在按钮独立的加法合成层内，不影响页面或旁边的翻译按钮。
- 圆角名义半径由 9 dp 调到 8 dp。该连续曲线实际占用的边长大于名义半径；9 dp 时约 18.1 dp，会超过 34 dp 宽按钮的半宽 17 dp，8 dp 时约 16.1 dp，可避免相邻角曲线重叠。
- 零尺寸的过渡帧不强制转换为 Generic Outline，避免意外的类型转换异常。
- 新增 Android 渲染回归，检查按下、激活展开、关闭收起过程中底边固定、底部中央未丢失、底角未被裁成直角。设备测试尚未执行。

## 开销

- 封面模糊移到 `Dispatchers.Default`，每个封面只做一次。使用 Float 通道上的三次滑动窗口盒式模糊近似 Gaussian，并保留 RGBA_F16 结果，避免反复 8-bit 量化。
- 移除动画帧中的全屏大半径 RenderEffect 模糊。改为柔化纹理、宽羽化的四层融合，以及最后的曝光/屏幕固定抖动。该路径仍有一个轻量的全屏颜色收尾效果，未宣称完全取消离屏渲染。
- 局部扭曲由逐像素计算改为 UV 网格。长边最多 64 个顶点，1080×2400 时为 28×64=1792 个顶点。屏幕顶点位置固定，复用坐标与索引数组，仅在扭曲角度或视口变化时更新 UV；GPU 负责三角形内的线性插值。
- 全图一致的图层旋转和轨道位置在 CPU 每帧计算一次，背景片段着色器不再调用 sin、cos、sqrt 或 length。切歌混合完成后只采样新封面。
- 每帧不创建、上传新的背景位图；新增的几何数据是可复用的 FloatArray/ShortArray，原生 drawVertices 会记录本帧几何数据。
- 仅显示迷你播放器或应用在后台时，直接准备最新封面，取消不可见的 900 ms 封面渐变。此前只停止流动相位，封面渐变仍可能以显示刷新率驱动绘制。重新打开时已经是最新封面。
- 封面处理结果使用进程内 LRU，最多六张 F16 纹理，约 3 MiB。重新打开页面立即使用缓存，并复用 Coil 的应用级 ImageLoader，不再反复创建/关闭加载器。淘汰缓存时不主动 recycle 仍可能被显示的位图。
- 自定义字体最多缓存一个 Typeface/FontFamily，按路径、修改时间和长度检查失效；减少重新进入页面时的字体文件加载。背景相位也保留至页面重新打开，避免重置到初始画面。
- 保留四层封面、72% 转速、暂停/迷你播放器/后台时停止相位更新、900 ms 连续切歌混合、既有歌词逐帧时钟和亚像素上浮。

## 验证与限制

- 本地 JVM 219 项测试通过，0 失败、0 错误；新增 Float 模糊的均匀色/透明度、对称性/能量、精度回归，以及网格比例、视口覆盖、缓冲区复用和反向运动回归。
- Release 和 Android 测试 APK 构建通过。ADB 无设备，按钮像素回归、Android AGSL 绘制和 GPU 帧耗时尚未真机验证。
- 使用当前两段实际着色器进行软件 Skia 离屏编译、UV 网格绘制与人工预览。横竖屏同一物理区域最大误差为 1 个 8-bit 色阶；0 秒与 12 秒平均 RGB 差约 11.819/255；纯色跨相位保持一致，暂停画面稳定，最终抖动范围 1 级，输出不透明。
- 对照从上个 Release APK 提取的实际背景着色器，在 480×1066 软件 Skia 中位耗时为旧路径 58.311 ms、新路径 58.401 ms，未观察到明显软件提速。这不是 Android GPU 测量，不能据此报告真机帧率改善。
- 对实际编译的 Kotlin 类做本地 JVM 微基准：1792 顶点更新平均约 0.0347 ms，256×256 Float 模糊平均约 3.2855 ms。前者不含原生几何记录/GPU 绘制，后者不含图片解码、Half 转换或纹理上传；也不代表手机耗时。
- 修复已降低渲染路径的逐像素计算、大半径模糊和重复资源加载开销，但整体掉帧是否消除仍需真机帧时间或用户实际体验确认。
