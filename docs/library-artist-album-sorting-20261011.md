# 歌手与专辑列表排序

- 歌手页右上角增加排序入口：歌手名、歌曲数量、专辑数量。
- 专辑页右上角增加排序入口：专辑名称、年份、更新时间、歌手名、曲目数量。
- 使用共用菜单弹窗，在当前选项显示方向箭头；两个页面分别持久保存排序方式和顺序，默认名称升序。搜索结果同样按当前规则排序。
- 名称使用完整拼音与大小写不敏感排序；主值相同时按名称稳定排列。
- 歌手歌曲数包含该歌手参与的合作曲目，每首曲目只计一次；专辑数按现有曲库的专辑名称分组方式去重，包括未知专辑分组。
- 年份取曲目发行年（缺少时取录制年），专辑中出现最多的年份优先，同票取较早年份，与现有专辑详情策略保持一致。
- 更新时间取专辑内最新有效修改时间；单曲缺少修改时间时回退添加时间。兼容 MediaStore 秒和远程文件毫秒时间戳。年份/日期缺失始终置后。
- 专辑按歌手排序优先使用专辑歌手标签，缺少时使用参与歌手的名称排序。
- 统计和各排序方式的升降序结果，在后台按曲库快照一次准备；切换方式时直接查表，无需重新启动异步排序任务。缓存只增加条目引用，不复制歌曲对象。列表项目复用分组歌曲及计数，不在逐行组合时重复扫描整个曲库。移除了专辑列表旧的固定 remember，重新进入页面或曲库快照变化会重算。

回归覆盖三种歌手排序、五种专辑排序、合作歌手去重、中文名拼音、年份投票、秒/毫秒兼容、未知日期置后、专辑歌手优先和曲库变化后的统计更新。实际页面交互尚未进行手机验证。

## 排序实时刷新修复

- 歌手页和专辑页切换排序及升降序时，立即选择缓存顺序，同时请求下一次测量回到顶部，避免 Lazy 列表按原可见条目 key 保持位置，造成看似没有刷新。
- 移除这两个页面的条目位置动画，避免大量项目重排与弹窗收起动画同时运行。
- Title 与网格标题组件允许传入页面持有的滚动状态，其余页面默认行为保持不变。
- 新增排序缓存回归：连续 1000 次选择不会再次排序，曲库更新后所有排序结果重新构建。

验证：128 项单元测试通过，Release 构建通过，git diff --check 通过。安装包已复制到下载目录；未进行实机页面交互和帧率验证。


## 二次定位：错误的 getter 稳定性声明

实际检查 Debug 编译产物发现：LocalArtists 的 remember(index, query, sortMode, descending) 只生成 index 和 query 的 changed 检查，排序方式和降序没有参与失效判断。根因是四个可变设置 getter 上的 @Stable 声明，让编译器错误地把它们当作相同输入下不变的结果。缓存优化本身无法解决这一点。

移除这四个 @Stable 标记，并增加使用真实 SettingsLibrary getter 的 Compose 设备回归，覆盖两个页面逐个切换排序方式和升降序，在没有其他状态更新时检查 remember 结果刷新。设备未连接，该交互回归仅编译，不宣称实机通过；同时检查编译产物是否恢复四个设置对应的 changed 检查。

编译产物核验结果：修复前歌手页该 remember 块仅有两个 changed(Object)；修复后歌手页和专辑页均增加 changed(Int) 和 changed(Boolean)，对应排序模式与降序。128 项单元测试通过，新增 Compose 设备测试 APK 编译通过；该测试尚未在设备上运行。


## 统一排序方向交互

歌曲列表（包括复用 NormalMusic 的列表）、歌手页、专辑页使用同一个排序菜单，移除单独的降序开关。点击非当前选项切换排序方式并保留方向；再次点击当前选项反转方向。当前项显示强调色的向上或向下箭头，并带有升序/降序无障碍说明。已有排序偏好继续保留。

歌曲排序的 SongSort 和 EnableDescending getter 同样移除错误的 @Stable 标记，避免状态变化被编译器从 Effect / remember 失效检查中遗漏。
