# 歌词选择页返回与开头间隔点击动画回归

## 问题与原因

- 长按打开歌词选择页后，底层帧时钟暂停。之前为消除返回时几秒钟的进度追赶，恢复后的首份报告直接同步播放时间，文字高亮因此直接跳到新进度。
- 开头的三个点期间点击第一句，原来的 seek 逻辑已在收起三个点前捕获滚动距离。但后来添加的实际绘制边界会按照三个点收起后的首行位置裁剪位移，把这段动画全部裁掉。此前的点击回归只覆盖歌曲中间的间隔；首端测试又只覆盖拖动，没有覆盖这两个行为的组合。

新增首端回归在修复前实际失败：第一句应保留 `125.8px` 的初始视觉位置，却直接跳到 `61.8px` 的最终位置，相差整个 `64px` 间隔槽位。

## 修改

- 播放时钟仍立即同步，用于确定最新跟随目标。单独保存绘制时间，选择页返回时从离开前的高亮进度过渡，在 300ms 内追上实时进度，之后恢复正常逐帧绘制。没有重新引入缓慢追赶的采样防抖路径，也不会让列表按所有错过的句子逐句滚动。
- 初次打开歌词不播放恢复动画；显式点击 seek 会立即取消未完成的恢复过渡，维持已有跳转语义。
- 从间隔行主动跳转时，记录当前间隔槽位高度。实际绘制边界只额外保留已收起槽位对应的空间，让开头第一句的已有弹簧位移正常播放；手指开始拖动或重置动画时清除这段保留空间，继续维持原有首端边界。
- 保留自然进入三个点时后续歌词静止、歌曲开头三个点保持高亮位置、正常逐行跟随和越界拖动限制。
