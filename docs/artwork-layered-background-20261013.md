# 播放页四层封面流动背景

当前在保留下述背景观感与参数的基础上，使用 [小尺寸 GPU 图层渲染](background-small-gpu-layer-20261013.md)，再平滑放大全屏，减少复杂背景场与后模糊开销。

按用户要求，背景已恢复到反馈“整体动画掉帧”之前的版本：四层封面 → AGSL 扭曲 → 整体 GPU 模糊 → 曝光与抖动，转速为 72%。后来加入的网格扭曲、纹理预模糊与色带参数调整已撤回；按钮圆角、矩形残边修复以及其他功能继续保留。恢复范围与验证见 [背景动画恢复记录](background-animation-restore-20261013.md)。

## 实现

参考 [Apple Music Web 的独立逆向分析](https://www.aadishv.dev/music) 中公开描述的处理顺序，自行实现 Android AGSL 版本：多层封面 → 局部扭曲 → 模糊 → 饱和度与曝光 → 输出抖动。这不是 Apple 原生客户端源码的移植，移动端的构图、速度和曝光参数由本项目调整。

- Android 13 及以上使用 256×256 的不透明 RGBA_F16 封面纹理。非正方形图片等比居中裁切，不再先压成正方形；移除播放页纹理准备阶段的两次 8-bit CPU 模糊和 1.7 倍饱和度增强。
- 四层封面各自保持正方形，坐标共用屏幕长边尺度。最大层放大至长边的 1.55 倍以适应竖屏和旋转；其余三层分别为 0.80、0.50、0.25 倍。较大两层自转，较小两层同时沿不同圆形/椭圆轨迹移动。
- 两个局部旋转扭曲场采用平方衰减，取代原先把单张纹理横纵拉动的正弦波。所有角度连续变化，没有动画循环重置点。
- RenderEffect 在四层融合之后执行 GPU 模糊，半径为屏幕短边的 18%。最后一个 RuntimeShader 将饱和度调整至 1.35 倍，并统一处理曝光。
- 根据真机反馈进一步柔化，并按后续要求略微加快：相位速度为第一版的 72%（此前依次为 45%、60%）；后三层权重分别为 0.65、0.65、0.50，扩大图层边缘羽化区，避免某一旋转封面突然占据画面。曝光参数保持不变，通过融合消除杂乱感。
- 最后加入约 ±0.6/255 的屏幕固定微量噪声，打散颜色量化边界；它位于模糊及曝光之后，避免被后续模糊消掉或压暗后再次量化。噪声不随时间变化，暂停时不会闪烁。
- 纹理使用 F16、着色器混色使用 float；GPU 中间表面的格式仍由 Android 渲染管线决定，不声称整个显示链路都为高精度或能够完全消除所有真机色阶。
- 保留 900 ms 切歌混合；快速连续切歌时，冻结已经混合的封面纹理并保留其精度。动态开关关闭、播放暂停、进入迷你播放器或应用进入后台时，停止相位更新。
- Android 12 及以下保留原先静态柔化兼容路径，但改成等比裁切显示，移除 FillBounds 拉伸。
- 分享歌词卡片的独立调色方案不在本次变更范围内，继续使用原来的 `prepareFlowTexture`。

- 离屏预览已人工查看，呈现融合的流动色团；这不替代 Android 真机的视觉、色阶和 GPU 性能验证。
- 速度从 45% 调到 60% 后，重新编译两段实际着色器并执行相同离屏检查，均通过；0 秒与 12 秒的平均 RGB 变化为 8.134/255，其余比例映射、纯色稳定、抖动及不透明输出检查通过。
- 速度进一步调到 72% 后，相同着色器编译和离屏检查通过；0 秒与 12 秒的平均 RGB 变化为 9.718/255，其余检查通过。
- 构建采用单次 Gradle daemon 和进程内 Kotlin 编译；构建结束后检查无 GradleDaemon / KotlinCompileDaemon 残留。
