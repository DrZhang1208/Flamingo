# 保留背景观感，降低逐帧渲染分辨率

用户反馈恢复旧背景后观感更好，但仍有卡顿。本次保持旧背景的处理顺序与全部着色器参数，将耗时的中间图层缩小。

## 渲染路径

1. 原 256×256 F16 封面纹理保持原样，不增加预模糊。
2. 使用 `Layout` 将子 Canvas 按视口宽高比测量为最长边至多 384 **物理像素**，通过 `placeWithLayer` 建立原生图层。四层封面、局部扭曲和合成后的 GPU 模糊均在这个小图层内执行。
3. 模糊半径仍为该图层短边的 18%，随图层等比放大后对应原来的视觉半径。
4. 使用线性采样放大到实际视口，最后按全屏坐标执行原曝光、饱和度和固定微量抖动，避免把小图层的噪声放大成颗粒。

四层尺寸、融合权重、约 30 Hz 相位时钟、900 ms 切歌渐变不变。用户确认这一版不卡后，按要求将转速由 72% 调至最初版本的 80%（相位系数 0.80），其他渲染和模糊参数不变。没有重新引入 UV 网格、纹理预模糊或后来调整的色带参数。

1080×2400 视口中，复杂背景场的记录尺寸为 173×384，像素数约为原来的 2.56%。这只描述复杂背景与模糊输入的规模，不等于总帧耗时下降 97.44%；全屏放大、曝光/抖动、歌词与其他界面绘制仍有开销。

## 复用与资源

- 原生图层由 Compose 管理生命周期，GPU 内处理，无逐帧位图创建、CPU 回读或位图上传。
- 相位变化只触发子 Canvas 绘制，不测量/布局整个播放页；暂停时停止相位循环。
- 全尺寸收尾图层明确设置 `clip = true`。收尾着色器输出不透明像素，若不裁切，在多个并排视口中会越界输出黑色，覆盖相邻背景。
- 恢复共享 Coil ImageLoader 与最多六张封面纹理的进程内 LRU，重新进入页面立即使用缓存。纹理处理本身仍为原 F16 等比裁切，缓存不会改变调色。
- 去除人声按钮、翻译、歌词和字体代码不变。

## 依据与验证边界

- [GraphicsLayer API](https://developer.android.com/reference/kotlin/androidx/compose/ui/graphics/layer/GraphicsLayer) 说明离屏栅格缓冲区采用记录时指定的尺寸；[Compose 图形文档](https://developer.android.com/develop/ui/compose/graphics/draw/modifiers) 说明 RenderEffect 强制离屏合成。
- 同时检查 [AOSP RenderNodeDrawable.cpp](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/libs/hwui/pipeline/skia/RenderNodeDrawable.cpp)：图层效果作用于其 raster surface 的快照，然后以 linear sampling 绘制。不是仅在全分辨率画面上改变采样坐标。
- 软件 Skia 编译两段当前实际着色器，用截图封面裁图和高饱和度渐变在 0/24 秒比较原全尺寸后模糊与小图层后模糊再放大。240×532 输出中，平均 RGB 差为 0.060–0.266/255，最大差为 1–3 个色阶；模拟 8-bit 中间图层时平均差为 0.141–0.304/255，最大差仍为 1–3 个色阶。人工查看对照图，融合区域一致。
- 同一 480×1066 软件 Skia 输出，8 次采样的耗时中位数为原路径 81.804 ms、小图层路径 20.719 ms，约 3.95 倍。该结果是本地 CPU 软件渲染对照，不是 Android GPU 测量，也不能换算成手机 FPS。
- 纯色跨相位画面稳定，最终抖动范围 1 色阶，输出不透明。
- 新增 JVM 尺寸回归覆盖横竖屏、方形、小视口、零尺寸与完整尺寸参考路径；Android 像素回归比较小图层与全尺寸参考，保留暂停、动态开关、迷你播放器、快速切歌、F16 和抖动测试。
- 真机初次并排对照中，收尾效果越界覆盖了左边的画面，导致左图看似变黑。强制重新记录和排除纹理格式/显示时机后仍复现，最终通过给收尾图层设置裁切边界消除；不能将该问题归因于静止帧复用。
- 在 HONOR BVL-AN00 / Android API 37 运行背景测试，6 项全部通过，包括小图层与全尺寸像素对照、暂停画面亮度/抖动、动态开关、移动、迷你模式与快速切歌。实际测试日志：`/tmp/flamingo-small-layer-clipped-tests.log`。
- 实际设备中，490×980 的高对比度条纹/红蓝区域夹具，对比完整分辨率参考，RGB 平均差为 0.311/255、最大差为 5/255，已人工查看保存的设备图像。
- JVM 216 项测试通过，0 失败/错误/跳过；最终 Release / Android 测试 APK 构建成功，`git diff --check` 通过。最终 Release 已通过 ADB 安装，并在真实歌曲歌词页检查背景显示；构建结束后无 Java/Kotlin 进程残留。
